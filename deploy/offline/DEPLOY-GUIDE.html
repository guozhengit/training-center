✓这一版是什么

上一版（20260908-fix1）是应急产物。当时的情况是：部署后健康检查一直 unhealthy，根因是 Jackson 版本冲突 —— fat jar 里 jackson-databind 被单独升到 2.19.0，其余 7 个组件还是 2.17.3，2.19 的 databind 调 JsonProperty.isRequired() 期望 OptBoolean 而 2.17.3 返回 boolean，于是 NoSuchMethodError。修复是删掉 pom 里那个只覆盖单个组件的版本声明，交回 Spring Boot 3.3.7 统一管理。

为什么当年没第一时间发现：/api/health 返回的是 Map，不走 bean 序列化所以一直是 200；而健康检查真正打的是返回 Health 对象的 actuator 端点，那里才炸。冒烟测试必须打健康检查实际用的那个端点。

这一版（20260914）做两件事：

  • 把修复固化成正式镜像：上一版是靠临时拼的 Dockerfile.rebuild 抠出来的，能跑但没法复现。这次换成正式的 deploy/offline/Dockerfile.offline，构建过程可重复。
  • 离线构建链路脚本化：新增 build-offline.ps1，一条命令完成「抽前端产物 → 构建 → 导出 → 算校验值」，下次更新不用再手搓。

本次冒烟实测：/api/health、/actuator/health、/、/index.html、/api/catalog/summary、/api/questions/filters、/api/stats、/api/history 全部 200，容器状态 healthy，题库 300 题（CODING 212 / ORAL 80 / PROJECT 8）可正常读取。

+以后怎么更新

代码改了之后，在本地跑一条命令就行（需要 Docker Desktop 开着）。它会自动从现有镜像抽取前端产物 → 构建 → 导出 → 算校验值：

cd D:\AI-SOURCE\training-center
.\deploy\offline\build-offline.ps1 -Tag 新版本号
为什么要用这个脚本而不是标准 Dockerfile？标准版第一步要 docker pull node:20-alpine 来编译前端，而本机连不上 Docker Hub（没有 HTTPS 代理，registry-1.docker.io 直接超时）。
脚本改走 deploy/offline/Dockerfile.offline：跳过前端编译，直接从已有镜像里把 BOOT-INF/classes/static 抠出来用。前端代码没改时这是安全的。
如果改了 training-ui：npm registry 是通的，在 training-ui 下跑 npm run build，然后把 FE_DIST 指向 training-center/training-ui/dist 即可（.dockerignore 已为它开例外）：
cd D:\AI-SOURCE\training-center\training-ui
npm run build
cd D:\AI-SOURCE
docker buildx build --builder desktop-linux --load \
  -f training-center/deploy/offline/Dockerfile.offline \
  --build-arg FE_DIST=training-center/training-ui/dist \
  -t training-center:新版本号 .
不要用 DOCKER_BUILDKIT=1 docker build：本机连不上 Docker Hub 时，它会去拉 moby/buildkit 镜像而超时失败。要用上面的 docker buildx build --builder desktop-linux --load。

然后把新的 tar.gz 拖到 /home/docker，执行：

cd /home/docker/training-center && bash deploy/linux/deploy.sh --image training-center:新版本号

旧容器会自动打上 rollback- 标签、数据会先备份再替换，出问题能退回去。

i几个要知道的限制

  • 只能单路判题：容器内存上限 1G + JVM 堆 256M，同时跑两路会 OOM。要并发得调大 TRAINING_MEMORY_LIMIT。
  • 目录沙箱 ≠ 安全隔离：判题进程和 Web 共用容器、用户和文件权限。这是给可信人员用的训练平台，不要开放给不可信用户提交代码。
  • SQLite 单实例：数据目录别挂到 NFS / CIFS 上。
  • 数据位置：/home/docker/training-data/training-runtime，备份在 /home/docker/backups。手动备份跑 bash /home/docker/training-center/deploy/linux/backup.sh。
