# Training Center 服务器部署指南

离线镜像方式：**本地构建镜像 → 导出归档 → scp 上传 → 服务器导入并切换**。
服务器不装 JDK/Maven/Node，也不需要访问 GitHub / Docker Hub。

> 基于 2026-10-08 实机部署（镜像 `training-center:20261008-fix2`）整理。
> 本地开发启动见 [本地启动指南](本地启动指南.md)，踩坑见 [部署问题与排查手册](部署问题与排查手册.md)。

## 3. 步骤一：准备构建上下文（关键，别直接用父目录）

`D:\AI-SOURCE` 下有 28 个兄弟项目且没有 `.dockerignore`，**直接当 build context 会上传几十 GB**。必须手工造一个干净上下文：

```bash
cd /d/AI-SOURCE
rm -rf _buildctx && mkdir -p _buildctx
cp -r training-center _buildctx/training-center

cd _buildctx/training-center
rm -rf .git .workbuddy .mimocode
find . -type d \( -name node_modules -o -name target -o -name dist -o -name __pycache__ \) -prune -exec rm -rf {} +
cd output && rm -rf doc pdf resume training-runtime interview-ai-agent   # 只留 coding-ai-exam 与 interview

cd /d/AI-SOURCE
mkdir -p _buildctx/_fe
cp -r training-center/training-ui/dist _buildctx/_fe/dist    # 前端产物（需先 npm run build）
du -sh _buildctx        # 约 125MB
```

## 4. 步骤二：构建镜像

```bash
cd /d/AI-SOURCE/_buildctx
docker buildx build --builder desktop-linux --load \
  -f training-center/deploy/offline/Dockerfile.offline \
  --build-arg FE_DIST=_fe/dist \
  --build-arg VCS_REF=20261008-fix2 \
  -t training-center:20261008-fix2 .
```

- 首次约 6~7 分钟，改源码后增量约 1~3 分钟。
- **不能用 `DOCKER_BUILDKIT=1 docker build`**：会去 Docker Hub 拉 `moby/buildkit`（不通），必须用 buildx + `desktop-linux`。
- Dockerfile 内会跑 `mvn package`（联网走阿里云镜像）与判题依赖预热。

## 5. 步骤三：导出归档

```bash
cd /d/AI-SOURCE
docker save -o _buildctx/img.tar training-center:20261008-fix2
gzip -9 -c _buildctx/img.tar > training-center-20261008-fix2.tar.gz
rm -f _buildctx/img.tar
tar -czf training-center-src-20261008-fix2.tar.gz training-center/deploy   # 只带部署脚本

sha256sum training-center-20261008-fix2.tar.gz      # 记下来，上传后比对
```

镜像归档约 **436MB**（层本身已压缩，`gzip -9` 几乎压不动），脚本归档约 40KB。

## 6. 步骤四：上传

```bash
KEY="C:/Users/gyz/.ssh/snnbook-k-lf5m04H0.txt"
scp -i "$KEY" training-center/deploy/offline/first-deploy.sh   root@120.48.23.3:/home/docker/first-deploy.sh
scp -i "$KEY" training-center-src-20261008-fix2.tar.gz         root@120.48.23.3:/home/docker/
scp -i "$KEY" training-center-20261008-fix2.tar.gz             root@120.48.23.3:/home/docker/   # 约 6 分钟

ssh -i "$KEY" root@120.48.23.3 "sha256sum /home/docker/training-center-20261008-fix2.tar.gz"
```

sha256 必须和本地一致（归档约 436MB，传输出错概率不低）。

## 7. 步骤五：导入并部署

**首次部署**（会展开源码、建数据目录、写 `.env`）：

```bash
cd /home/docker && \
IMAGE_ARCHIVE=/home/docker/training-center-20261008-fix2.tar.gz \
SRC_ARCHIVE=/home/docker/training-center-src-20261008-fix2.tar.gz \
TRAINING_PORT=9091 bash first-deploy.sh
```

**后续更新**（脚本、`.env` 已就位，跳过导入重复步骤）：

```bash
cd /home/docker && gunzip -c training-center-20261008-fix2.tar.gz | docker load
cd /home/docker/training-center && \
  docker compose -f deploy/docker-compose.yml -f deploy/linux/docker-compose.prod.yml config -q && \
  bash deploy/linux/deploy.sh --image training-center:20261008-fix2
```

`deploy.sh --image` 做的事：**给旧镜像打 `training-center:rollback-<时间戳>` → 备份数据 → `up -d --force-recreate --wait` → 等健康 → 记录 releases.log**。等健康通过才完成，失败会保留现场。

## 8. 步骤六：验收

```bash
docker ps --filter name=training-center --format '{{.Names}} | {{.Image}} | {{.Status}}'
curl -fsS http://127.0.0.1:9091/api/health
curl -s -o /dev/null -w '%{http_code}\n' https://train.sageflow.online/

# 关键：带 Origin 复现浏览器写操作（不带 Origin 永远 200，会误判）
curl -s -o /dev/null -w '%{http_code}\n' -X POST \
  -H 'Content-Type: application/json' -H 'Origin: https://train.sageflow.online' \
  -d '{"track":"CODING","count":3}' https://train.sageflow.online/api/training/sessions

docker logs --tail 100 training-center
```

期望：容器 `Up … (healthy)`、health 返回 `status:UP`、域名与抽题接口均为 200。

## 9. 环境变量（`deploy/linux/.env`，由 first-deploy.sh 生成）

| 变量 | 默认 | 说明 |
|---|---|---|
| `TRAINING_PORT` | 9091 | 对外端口 |
| `TRAINING_DATA_DIR` | `/home/docker/training-data` | 数据父目录（bind mount） |
| `TRAINING_MEMORY_LIMIT` / `TRAINING_CPU_LIMIT` | `1G` / `1.0` | 容器资源上限 |
| `JAVA_OPTS` | `-Xms64m -Xmx256m -XX:+UseContainerSupport` | 堆 256m，只能单路判题，勿并发 |
| `BASE_IMAGE` | `training-center-base:17` | 基础镜像 |
| `TRAINING_API_KEY` | 空 | 非空时 `/api/**` 需 `X-API-Key` 头 |
| `TRAINING_CORS_ALLOWED_ORIGINS` | `https://train.sageflow.online,http://120.48.23.3:9091` | **必须包含真实访问来源，否则写操作 403** |
| `TRAINING_REDIS_HOST/PORT/USERNAME/PASSWORD` | 空 | 留空则不启用缓存 |

## 10. 回滚

```bash
docker images | grep rollback          # 找到 rollback-<时间戳>
cd /home/docker/training-center && bash deploy/linux/deploy.sh --image training-center:rollback-20261008T164556-721131
```

数据快照在 `/home/docker/backups/training-data-<时间戳>.tar.gz`（保留最近 7 份）。
⚠️ 若新版本改过数据库 schema，回滚前务必先确认兼容性。

## 11. 数据与日志

- 数据库：`/home/docker/training-data/training-runtime/database/training.db`
- 应用日志：**容器内 CWD=`/workspace`**，日志落在 `output/training-runtime/logs/`（即宿主机 `.../training-runtime/logs/app.log`、`diag.log`），随 bind mount 持久化。
- 容器以 **uid 1000** 运行，所有可写路径都已 `chown 1000`；新增写路径时注意权限。
- 发布记录：`/home/docker/training-data/releases.log`
